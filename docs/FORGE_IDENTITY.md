# Forge 身份定义与最高判定规则

## 一、Forge 是什么

Forge 是一个独立存在、可在不同载体上运行的开放软件系统。

它的核心不是某种安装包、某个平台、某个 AI 模型、Veritas、
某个用户的数据或某一个项目。这些都可以变化。

Forge 的核心是：

无论以什么技术形态安装到什么载体上，
用户最终得到的都是一个可以启动、接入 AI、
接受自然语言目标并执行工作的 Forge 系统。

APK、Linux 包、Termux、Docker、网页、桌面客户端
都只是 Forge 的不同载体形态，不是不同的 Forge。


## 二、最高判据

Forge 是在以下外部条件被替换后，
其核心身份与行为原则仍然成立的东西：

- 平台 / 载体
- 安装方式
- AI 模型
- 是否连接 Veritas
- 用户项目
- 用户数据与历史
- 运行时产生的状态
- 当前具体实现

只要这些变化后 Forge 仍然是 Forge，
它们就不属于 Forge 的身份本体。

注意：
"换掉后 Forge 仍然存在"只能证明某东西不是 Forge 的身份条件，
不能自动证明它对 Forge 的当前实现毫无必要。
当前实现需要但未来可替换的，不属于 Forge 身份本体。


## 三、五问：身份裁判

任何东西是否属于 Forge 身份本体，用以下五问判断。

1. 换载体，还是 Forge 吗？
   APK、Linux、Termux、容器、网页等都只是载体。
   平台不能定义 Forge。

2. 换 AI，还是 Forge 吗？
   模型是可替换的智能来源。
   AI 不能定义 Forge。

3. 不连 Veritas，还是 Forge 吗？
   是。
   Veritas 是可选连接的机器能力。
   Veritas 不能定义 Forge。

4. 换用户项目，还是 Forge 吗？
   是。
   用户项目、代码、Git、产物都是 Forge 操作的外部世界。
   用户项目不能定义 Forge。

5. 被修改、重构、重新构建后，还是 Forge 吗？
   可以。
   被修改之后，只要仍满足 Forge 的身份原则，
   它仍然是 Forge。
   某一个固定版本不能定义 Forge。


## 四、层次归位

以后遇到任何东西，先问它属于哪一层，
不要直接把"当前仓库里有"等同于"Forge 本体"。

### 第一层：Forge 身份原则

真正定义 Forge 的东西：

- 独立软件系统
- 开放、可演化
- 不绑定特定载体
- 有统一的"用户目标 → 执行"入口
- 可接入可替换的 AI，作为智能执行能力来源
- 不绑定特定 AI，但必须接入某个可用 AI，才能进入运行状态
- 可在普通计算环境运行
- 可选择连接 Veritas
- Veritas 不是 Forge 运行的必要条件
- 能作用于外部世界；读取不依赖 Veritas，变更依赖连接 Veritas
- 在条件允许时可以参与演化自身

这些不是当前仓库的文件结构，
而是 Forge 即使换一种实现，也必须保留的身份原则。

### 第二层：Forge 的当前实现

当前属于这一层的东西：

- Python
- Termux 中的运行方式
- dp.py 入口
- Runtime.run 主循环
- Tools 与工具循环
- TUI / CLI
- JSONL 进程接口
- .forge/ 当前状态布局

这些可以变化，甚至未来可能被替换。
当前实现需要，不等于身份定义。

### 第三层：运行环境

- Termux
- Linux
- Android
- Container
- Web
- 桌面

运行环境会变。环境不能定义 Forge。

### 第四层：外部对象与产物

- AI 模型
- API Key
- Veritas 机器
- 用户项目
- 用户数据
- Git 历史
- Forge 对外操作产生的产物

这些都不是 Forge 本体。
Forge 可以操作它们、连接它们、使用它们，
但不拥有它们，也不由它们定义。


## 五、最重要的一条规则

不能再用"我们现在的仓库"去定义 Forge。

原型仓库同时包含：

- Forge 原型
- Forge 当前实现
- 开发环境
- 测试与调试历史
- 身份痕迹
- 可能的 Veritas 相关内容
- 用户工作区绑定

而产品意义上的 Forge 只是其中那个：

可以被独立拿出来，在不同环境中安装、启动、
接入 AI，并让用户通过目标来使用的系统。

凡是在"Forge 本体、当前实现、运行环境、外部对象"
之间混淆的讨论，一律先回到本文件重新归位。


## 六、Forge 身份摘要

Forge 是一套稳定身份原则之下的开放、可演化、
跨载体、目标驱动的软件系统。

当前实现、运行环境、AI、Veritas、用户项目和历史
都属于可替换层，不参与定义 Forge 本身。

核心判定只有一句：

换平台、换模型、断开 Veritas、换用户项目之后，
如果它仍然是 Forge，那么这些东西就不是 Forge 的本体。

AI 与 Veritas 的地位不同：

- AI 是可替换的，但“存在一个可用 AI”是 Forge 进入运行状态的必要条件。
- Veritas 是可选择的，不连接 Veritas，Forge 仍可运行，处于只读工作形态。


## 七、后续设计边界

以下问题不能在未通过身份裁判前进入具体开发讨论：

- Forge Distribution 打包格式
- 是否内嵌或托管 veritasd
- .forge/ 目录最终布局
- A2A / 多端 / headless 产品化
- 自动 diff 是否写入默认协议
- 子 Agent 是否协议化
- 安装脚本与迁移工具

必须先用本文件判断：

它是身份原则吗？
它只是当前实现吗？
它是运行环境吗？
它是外部对象或用户产物吗？

否则不得进入下一阶段设计。
