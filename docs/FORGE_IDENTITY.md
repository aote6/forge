# Forge 身份定义与最高判定规则

状态：有效

讨论「这是不是 Forge / 算不算本体」时用本文件。
不替代实现说明；能力通断见 `FORGE_VERITAS_STANCE.md`。

## 一、Forge 是什么

Forge 是一个独立、可在不同载体上运行的开放软件系统。

核心不是某个安装包、某个平台、某个模型、Veritas、某个用户项目或某次运行状态。

用户最终得到的是：能启动、能接 AI、能接受目标并动手干活的工程 Agent 系统。  
Termux、Linux、容器、桌面等只是载体，不是不同的 Forge。

## 二、最高判据

下列被换掉之后，若仍满足身份原则，则它们不是身份本体：

- 平台 / 载体、安装方式
- AI 模型
- 是否连接 Veritas
- 用户项目与数据
- 运行时状态、当前具体实现

注意：「换掉仍是 Forge」只说明不是身份条件，不说明当前实现不需要它。

## 三、五问

1. 换载体？仍是 Forge。平台不定义 Forge。  
2. 换 AI？仍是 Forge。模型可替换。  
3. 不连 Veritas？仍是 Forge。Veritas 是可选连接的机器能力，不定义身份。  
4. 换用户项目？仍是 Forge。项目是外部世界。  
5. 重构后？只要仍满足身份原则，仍是 Forge。固定版本不定义 Forge。

## 四、层次

**身份原则（应长期保留的方向）**

- 独立、开放、可演化，不绑死单一载体
- 统一的「目标 → 执行」入口
- 可接可替换的 AI；没有可用 AI 则不能作为 Agent 工作
- 可选择连接 Veritas；Veritas 不是身份必要条件
- 能作用于外部世界（读、跑命令、以及实现所提供的写入路径）
- 条件允许时可参与演化自身

**当前实现（可换）**

Python、`dp.py`、Runtime、工具循环、TUI/CLI、JSONL、`.forge/` 布局等。

**运行环境（可换）**

Termux、Linux、Android、容器、Web、桌面等。

**外部对象**

模型与 Key、Veritas 机器、用户项目与 Git、运行产物等。

## 五、不要用「当前仓库」定义产品

原型仓里混有实现、调试史、联调假设、工作区痕迹。  
产品意义上的 Forge 是可拿出来安装、接 AI、按目标使用的那套系统，不是仓库目录的总和。

## 六、摘要

- AI：可替换，但是否存在可用 AI 决定能否作为 Agent 工作。  
- Veritas：可选择连接；不连接时仍是 Forge，且当前实现下探索/规划等仍可用，事务写入主路径不可用（详见 VERITAS 立场）。  
- 身份问题与「这一版代码具体通不通某条写路径」分开谈。

## 七、后续实现讨论前

打包格式、是否内嵌 veritasd、目录最终布局、A2A 等，先分清是身份、实现、环境还是外部对象，再进方案；避免把实现细节写进身份。
